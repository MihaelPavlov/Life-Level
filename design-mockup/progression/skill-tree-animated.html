Animation states (from the source video breakdown)

  • A · Overview — full radial graph, ±2px floating drift, soft hub pulses, low-opacity edges.
  • B · Category select — camera tweens toward the hub with cubic-bezier(0.22,1,0.36,1), other branches fade to 8% opacity.
  • C · Title transition — category name flashes full-bleed for ~400ms while the graph dims.
  • D · Branch reveal — root pulses, edges draw in, children scale in staggered by index * 90ms, labels fade in last.
  • E · Node inspection — selected node scales to 1.15 with a ring + glow, unrelated nodes dim to 0.25 opacity, a detail sheet slides up.
  • F · Return — reverse of B/D: sheet closes, camera eases back to {x:0, y:0, zoom:0.5}, branches fade back in.

Recommended production stack

This mockup is a single dependency-light HTML file (vanilla JS + SVG + GSAP via CDN for camera tweening) so it's easy to open and review. For the real in-app build, the source doc recommends:

PixiJS
WebGL rendering for hundreds of nodes/particles + glow
d3-hierarchy
One-time radial tree layout calculation
GSAP
Camera + stagger tweens (already used live here)
TypeScript
Graph model (GameGraphNode / GameGraphCategory) + state machine

In Flutter this maps to a CustomPainter canvas for edges/particles + AnimatedPositioned/flutter_animate for node transforms, with an explicit GraphViewState enum (overview / opening / category / node / closing) instead of PixiJS.

How it maps to Life-Level's Adaptive Skill Tree

Center = Class root (Ranger). The 8 hubs are the 4 Behavior branches (Power, Momentum, Focus, Hybrid) and 4 Motivation branches (Explorer, Hunter, Discipline, Tactician) from the game-design plan. Each hub's children reuse the plan's example perks (First Wind, Pathfinder, Boss Instinct, Shielded Will, Hybrid Spark, etc.) tagged by node type — Quest, Travel, Boss, Streak, Identity.

The dashed ring around the center particle cloud is the hidden mastery branch: it stays inert until 3 different branches have been explored, then invites a tap into the Trailborn reveal — the plan's "this is who I became" moment.

This is a design/animation prototype, not production code. Node positions use one frozen radial layout (hub + outward fan) with camera zoom for both overview and detail — the source doc recommends two separate precalculated layouts (Stage 1/Stage 2) for a production build once branches get denser.
