SCHEDULER
Spawn dial · per-zone
Each zone has a 5–24h cooldown · NPC type rolled by rarity weights · cap 4 per user globally
9:41●●● 🔋
Spawn pipeline
1
Hosted service tick (every 15 min)
For each user, scan unlocked zones. Pick zones whose last_spawn_at + cooldown < now.
2
Roll archetype · weighted
Trainer 50% · Merchant 30% · Hunter 15% · Sage 5%. Boosted by player level (Sage gates after Lvl 15).
3
Cap check · max 4 active per user
Prevents NPC spam. If at cap, oldest (lowest priority) NPC is replaced — Sage is sticky, others get evicted first.
4
Persist + push notify
Insert RandomNpc row, fire NpcSpawnedEvent. FCM push uses LL-013 cadence policy (no spam in 4h window).
EXPIRY
Each NPC has its own expires_at. A janitor pass on every tick despawns expired ones. Trainer/Merchant: 5–12h. Hunter: 24–72h (bounty length). Sage: 7d.

📍 How NPCs choose where they appear

On the World Map (region cards)

  • Each region card shows up to 3 NPC pin badges in its banner pin row, ranked by rarity (Sage > Hunter > Merchant > Trainer).
  • If >3 NPCs alive, the card gets a +N more pin and the rest are visible only inside the region.
  • The active region also gets the dashed callout strip listing the 3 most relevant NPCs by name + zone.
  • Locked regions get nothing. The spawner skips zones the user can't enter — keeps the worldmap honest.

On the Region Detail (zone trail)

  • NPCs never overlap zone bubbles. They live in a horizontal scrolling strip placed above the trail (between banner and "Your path" section title).
  • Each card carries: archetype-coloured avatar, role label, NPC name, anchor-zone tag (where they're standing), and a timer with chevron.
  • Tap the card → opens the NPC sheet. The trail stays clean and readable; NPCs are always one glance away but never compete with the path visuals.
  • Bosses and Crossroads never get NPCs — they have their own narrative weight, NPC clutter would compete.

Anchor zone selection (per spawn)

When the spawner rolls a new NPC for a region, it picks the anchor zone like this:

  1. Filter: only zones that are Completed or Active for that user — no spawning on zones they haven't reached.
  2. Exclude: Boss zones, Crossroads zones, the destination of the user's active journey (don't blocking-clutter their next bubble).
  3. Weight by recency: zones the user has visited in the last 7 days get 3× weight — keeps NPCs near where they're actively playing.
  4. Diversity tax: if the same zone already hosts an NPC, halve its weight (avoid all four NPCs on one bubble).
  5. Pick: weighted random.

Visual states on the trail

  • Spawn (just appeared): outer ring pulse for ~6 seconds, plus the SPAWN · just now sub-label on the parent zone for a few minutes.
  • Active: normal pulse, full opacity.
  • Expiring (<2h): timer pill turns amber; token slightly desaturated.
  • Gone: token removed; replaced by a faint 👣 footprint card under the trail listing the last 5 expired NPCs (helps users learn the rhythm).

🗂 Data model sketch

Currency

Add to UserCharacter aggregate (Identity module):

public class UserWallet {
  public Guid UserId { get; set; }
  public long Coins { get; set; }
  public int Gems { get; set; }
  public Dictionary<Guid, int> EventTokens { get; set; }
  public DateTime UpdatedAt { get; set; }
}

Why a single wallet aggregate: a transaction can debit/credit multiple currencies atomically. Tokens are a dict because seasons come and go.

NPC entity

Lives in a new LifeLevel.Modules.RandomEvents module (or extend the existing one):

public class RandomNpc {
  public Guid Id { get; set; }
  public Guid UserId { get; set; }
  public Guid ZoneId { get; set; }
  public NpcArchetype Archetype { get; set; }
    // Trainer | Hunter | Sage | Merchant
  public NpcRarity Rarity { get; set; }
  public DateTime SpawnedAt { get; set; }
  public DateTime ExpiresAt { get; set; }
  public string PayloadJson { get; set; }
    // typed deserialise based on Archetype
  public NpcStatus Status { get; set; }
    // Active | Accepted | Completed | Expired | Failed
}

Ledger

One immutable row per currency change — debug, fraud detection, fair-play audits:

public class WalletLedgerEntry {
  public Guid Id { get; set; }
  public Guid UserId { get; set; }
  public CurrencyKind Currency { get; set; }
  public long Delta { get; set; }     // signed
  public long Balance { get; set; }   // post-tx
  public string Source { get; set; }
    // "activity" | "quest" | "boss"
    // | "merchant.purchase" | "trainer.complete"
    // | "bounty.complete" | "achievement"
  public Guid? RefId { get; set; }
  public DateTime At { get; set; }
}

Endpoints

  • GET /api/wallet — current balances + last 20 ledger entries
  • GET /api/npcs/active — active NPCs for the user
  • POST /api/npcs/{id}/accept — accept Trainer challenge / Hunter bounty / Sage step
  • POST /api/npcs/{id}/complete — server validates + grants payload
  • POST /api/wallet/spend — atomic spend with idempotency key (replaces direct purchase endpoints)

❓ Open questions for next iteration

Economy

  • Is there a daily coin cap to prevent farming, or do we lean on the per-source caps only?
  • Does buying gems with real money exist on day 1, or are gems milestone-only first?
  • Trade between players? (Out of scope for v1, but the wallet ledger model supports it.)
  • Refund / regret window for accidental purchases?

NPCs

  • Should NPCs have reputation per archetype that unlocks better stock / harder bounties?
  • Multiplayer: can a Hunter bounty be co-op? (Could turn into a guild raid hook.)
  • Sage riddles: hand-curated content vs. templated? Templated scales but feels generic.

Spawn / fairness

  • Should NPC spawns be shared within a guild (so members meet at the same NPC) or per-user?
  • Pity timer if a user goes 24h without any NPC at all?
  • What happens when a user has zero unlocked zones (Lvl 1 onboarding)? Probably guarantee a Trainer at the starter zone.

Tickets to spin off

  • LL-011a — Wallet aggregate + ledger + spend endpoint
  • LL-011b — Currency display in HUD + wallet screen
  • LL-011c — Trainer NPC (smallest archetype, pilot)
  • LL-011d — Hunter NPC + bounty integration with mini-boss system
  • LL-011e — Sage NPC + lore quest content pipeline
  • LL-011f — Wandering Merchant (the original ticket, but now using shared spawn engine)
