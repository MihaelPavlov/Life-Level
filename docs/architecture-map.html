Cross-Module Communication
⚡ Tier 1 — Synchronous Port Calls
Same transaction, direct interface injection. Used for data that must be consistent.
  • Activity→ICharacterXpPort.AwardXpAsync()
  • Activity→ICharacterStatPort.ApplyStatGainsAsync()
  • Activity→IWorldZoneDistancePort.AddDistanceAsync()
  • Character.GetProfile→IStreakReadPort, ILoginRewardReadPort, IDailyQuestReadPort
  • LoginReward→IStreakShieldPort.AddShieldAsync()
  • Boss→ICharacterXpPort.AwardXpAsync()
📡 Tier 2 — Domain Events (fire-and-await)
After SaveChanges. Used for side-effects that don't need to be in the same transaction.
  • ActivityLoggedEvent→StreakActivityHandler
  • ActivityLoggedEvent→QuestActivityHandler
  • UserRegisteredEvent→CharacterCreatedHandler
  • StreakBrokenEvent→StreakBrokenNotificationHandler → FCM push
  • CharacterLeveledUpEvent→LevelUpUnlockHandler (items/zones/titles)

Key Architectural Constraints
✅ AppDbContext Rule
Single AppDbContext in LifeLevel.Api (41 DbSets). Each module provides IEntityTypeConfiguration<T> classes. ApplyConfigurationsFromAssembly() called per module in OnModelCreating. Migrations live in LifeLevel.Api only.
✅ Port Rule
Modules never reference each other's concrete classes. All cross-module calls go through port interfaces defined in SharedKernel. Concrete implementations live in the implementing module and are registered in LifeLevel.Api DI container.
✅ Seeder Rule
WorldSeeder lives in LifeLevel.Api (touches World/Zone/Node entities from multiple modules). Composition root is the right place for cross-module seeders.
✅ Auth Rule
Supabase Auth is NOT used. JWT HS256 issued by ASP.NET Core Identity module. Tokens expire in 24h. All auth logic stays in the backend — never delegated to Supabase.

XP Formula
ActivityService.CalculateGains()
var baseXp = durationMinutes × 10; // 10 XP per minute var typeModifier = activityType switch { Run, Cycle → 1.00, Swim → 1.20, // +20% Walk → 0.75, // -25% Sport → 1.10, // +10% Strength → 1.30, // +30% Yoga → 0.90, // -10% Custom → 1.00, }; var gearBonus = IGearBonusReadPort.GetEquippedBonusesAsync(userId).XpBonusPct; var finalXp = (int)(baseXp × typeModifier × (1 + gearBonus / 100)); // XP Storm ×2 (LL-001): finalXp ×= 2 when LoginReward.IsXpStorm == true — NOT YET WIRED

Note: Gear bonus (XpBonusPct) comes from equipped items via IGearBonusReadPort. XP Storm multiplier (Day 7 login reward) is tracked but not yet applied — see ticket LL-001.

Level Progression
CharacterService — Level Threshold Formula
// XP required to reach level N (cumulative): threshold(N) = N × 1000 Level 1 → 1,000 XP | Level 6 → 6,000 XP Level 2 → 2,000 XP | Level 7 → 7,000 XP Level 3 → 3,000 XP | Level 8 → 8,000 XP Level 4 → 4,000 XP | Level 9 → 9,000 XP Level 5 → 5,000 XP | Level 10 → 10,000 XP // On level-up: fires CharacterLeveledUpEvent → // LevelUpUnlockHandler: UnlockTitles, UnlockZones, GrantItems // Mobile: shows level-up overlay via LevelUpNotifier (static stream)
Boss Damage Formula
BossService.CalculateDamageFromActivity()
baseDamage = (durationMinutes / 30) + (int)(distanceKm / 2.0) typeMultiplier = activityType switch { Walk → 0.5, Run → 1.0, Cycle → 1.0, Swim → 1.5, Strength → 2.0, Sport → 1.5, Yoga → 0.5, Custom → 1.0, }; finalDamage = max(1, (int)(baseDamage × typeMultiplier)) // Boss HP ranges: 100–500+ (regular), smaller for mini // Timer: 7 days (regular boss); IsExpired set after TimerDays // Defeat: HpDealt ≥ MaxHp → IsDefeated = true → AwardXp
Streak Rules
Streak Lifecycle
Daily activity logged → streak.Current++ No activity for 24h + no shield → BREAK streak.Current = 0 streak.LastStreakBrokenAt = now fires StreakBrokenEvent → FCM push Shield use (before break): streak.Shields-- streak.ShieldUsedToday = true streak.Current preserved Shield accrual: every 7 active days Max shields: 3 (configurable) Day 7 of login cycle → sets IsXpStorm flag on LoginReward
Streak Milestones
Milestone thresholds: [3, 7, 14, 30, 60, 100] days 7-day login reward cycle: Day 1: +100 XP Day 2: +150 XP Day 3: +200 XP Day 4: +250 XP Day 5: +300 XP Day 6: +400 XP Day 7: +500 XP + IsXpStorm flag + 1 Shield 30-day milestone: legendary cosmetic (planned LL-038) At-risk notification at 20h idle (planned LL-036)
Quest Generation
QuestService.GenerateDailyQuestsAsync()
// 5 quests assigned per user per day, at UTC midnight reset // Templates randomly selected from active Quest pool // ExpiresAt = next midnight UTC Progress via: QuestActivityHandler (ActivityLoggedEvent) → IQuestProgressPort.RecordActivityProgressAsync(userId, type, value) Completion: CurrentValue ≥ Quest.TargetValue Reward: Quest.RewardXp (100–500 XP range) All-5-daily bonus: +50 XP when all 5 complete in same day Weekly quests: 3 quests (e.g. "3 workouts this week", "10 km running")
Zone Travel Rules
WorldZoneService.AddDistanceAsync() via IWorldZoneDistancePort
On activity log: Activity.DistanceKm → IWorldZoneDistancePort.AddDistanceAsync(userId, km) UserWorldProgress.DistanceTraveledOnEdge += km Visual position on edge: progress% = DistanceTraveledOnEdge / WorldZoneEdge.DistanceKm Arrival condition: DistanceTraveledOnEdge >= WorldZoneEdge.DistanceKm → zone-arrival banner shown on mobile → destination zone unlocked → auto-spawns zone boss if applicable Zone unlock requirements: WorldZone.UnlockLevel <= Character.Level Set destination: POST /api/world-zones/{id}/set-destination

Key Data Flows
📱 → POST /api/activity/log
1
Mobile sends activity
type, durationMinutes, distanceKm, calories, heartRate
2
ActivityService.CalculateGains()
XP = minutes×10 × typeModifier × gearBonus. Stat gains by type.
3
Sync port calls (same txn)
ICharacterXpPort → level-up check. ICharacterStatPort → stat update. IWorldZoneDistancePort → edge progress.
4
Activity entity saved
Activity record persisted to DB.
5
Domain events fired (after SaveChanges)
ActivityLoggedEvent → StreakActivityHandler (increment streak), QuestActivityHandler (update quest progress). Tutorial gate check.
6
Response returned
{xpGained, statGains, leveledUp, newLevel, xpStorm}
⬆️ Level-Up Flow
1
ICharacterXpPort.AwardXpAsync()
Called from Activity or Boss defeat. XP added to Character.Xp.
2
Level check: Xp ≥ Level × 1000?
If yes: Character.Level++, Character.AvailableStatPoints++
3
CharacterLeveledUpEvent fired
LevelUpUnlockHandler runs: grants items via ILevelUpItemGrantPort, unlocks zones, unlocks titles (if UnlockLevel == newLevel).
4
Mobile overlay triggered
ActivityService returns leveledUp:true → mobile fires LevelUpNotifier static stream → MainShell shows level-up overlay.

POST /api/auth/register
{username, password}

UserRegisteredEvent fired

🌍 Zone Travel Flow
1
User sets destination
POST /api/world-zones/{id}/set-destination → UserWorldProgress.DestinationZoneId set.
2
Each activity adds distance
Activity.DistanceKm → IWorldZoneDistancePort.AddDistanceAsync() → UserWorldProgress.DistanceTraveledOnEdge += km.
3
Mobile shows progress
GET /api/world-map → DistanceTraveledOnEdge / edge.DistanceKm = progress %. WorldMapDetailSheet shows bar.
4
Arrival
Progress ≥ 100% → zone unlocked → arrival banner → zone boss auto-spawned if configured.
